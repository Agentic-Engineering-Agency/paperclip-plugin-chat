# v0.3.0 — In-chat agent selection, expanded settings, sidebar nav fix

Date: 2026-07-07

## Summary

You can now pick a specific hired agent for a chat thread from inside the chat
UI instead of only choosing a runtime/adapter in plugin settings. Plugin
settings were expanded, and two blocking UI bugs were fixed: the sidebar "Chat"
entry now opens the full chat page (previously routed to settings), and the
screen-breaking chat overlay was removed.

## Added

- **In-chat agent picker.** New/empty threads show a prominent picker listing
  every existing hired agent (`ChatAgentInfo`) plus an "Auto" option that falls
  back to adapter/runtime auto-selection. The chosen agent is persisted on the
  thread (`agentId`/`agentName`) and **locked once the thread starts** (first
  `sendMessage`, when the `sessionId` is cached). Switching agents mid-thread
  requires starting a new chat. A "locked for this thread" label surfaces the
  bound agent.
- **Expanded plugin settings.** Added `Default Agent ID`, `Default Model`,
  `Streaming Enabled`, `Show Tool Calls`, and `Enrich Context` config fields.

## Fixed

- **Sidebar "Chat" opened settings instead of the chat page.** The `page` slot
  now declares `routePath: "chat"`, and the sidebar entry links via
  `useHostNavigation().linkProps("/chat")` (canonical `WikiSidebarLink`
  pattern), landing on `/<prefix>/chat`. The page route is `/plugins/:pluginId`
  (UUID) or the clean `routePath` alias — never `/plugins/<key>`, which the host
  resolves to plugin settings. (Closes webprismdevin/paperclip-plugin-chat#2.)
- **Screen-breaking chat popup.** Removed the `sidebarPanel` slot
  (`ChatSidebarPanel`) that rendered a `fixed inset-0 z-50` full-viewport
  overlay embedding the whole chat page with no way to close or interact.
- Removed the misconfigured `launcher` whose `target` resolved to the plugin
  settings route.

## Changed

- Replaced the `sidebarPanel` UI slot with a native `sidebar` slot
  (`exportName: "ChatSidebarLink"`), matching the Aperture/Wiki pattern.
- Repurposed the orphaned error boundary to wrap the page
  (`ChatPageInner` + `ChatPageErrorBoundary`), hardening against render-error
  blank/broken screens.

## Verified

- Reinstalled into the running Paperclip instance (`status: ready`,
  `version 0.3.0`).
- Sidebar **Chat** → `<a href="/<prefix>/chat">` → full-screen chat page, not
  settings; zero screen-breaking fixed overlays.
- In-chat picker lists all existing agents + Auto; selecting an agent and
  sending locks the thread to that agent.
- Settings page renders all five expanded fields.
- `npm run typecheck` and build green.
